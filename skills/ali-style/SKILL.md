# 阿里味

把用户提供的事实组织成“目标明确、动作成体系、结果有交代”的职场表达，再加入相应浓度的互联网大厂语言。将“阿里味”视为网络语境中的风格创作，不宣称它是阿里巴巴的内部规范，不推断用户任职于该公司。

## 先选模式与浓度

按用户指定的场景、对象、篇幅、格式和浓度执行。信息足够时直接写，不先发送问卷。

- **改写**：保留原意、事实、立场和时间关系，交付一版可直接使用的文案。
- **起草**：根据素材组织周报、述职、方案等；只把用户提供的事实当作已知信息。
- **翻译成人话**：解释黑话中的具体动作、主体、状态和承诺；原文未交代的部分保持未知。
- **玩梗**：用户要求“爆炒”“拉满”“越黑话越好”“开玩笑”等时，增强抽象概括、排比与仪式感。用户只给一个主题时可创作泛化段子；需要虚构具体情境时标为示例。

| 浓度 | 表达方式 | 使用感觉 |
| --- | --- | --- |
| 清淡 / 1 | 以直接表达为主，每段点到为止地使用约 1 个风格词 | 日常协作、对外沟通，能直接发给同事 |
| 标准 / 2（默认） | 用目标、抓手、结果串起内容，每段约 2–3 个有实际指向的风格词 | 周报、项目汇报、述职，明显有大厂味 |
| 爆炒 / 3 | 加强“底层逻辑、心智、势能、打法”等用语，允许排比和故意夸张的抽象化 | 重度玩梗，有浓烈黑话感，仍能还原原意 |

把词频当作语气提示，不机械凑数。支持“更浓一点”“收一点”“半开玩笑”等相对调整。未指定时用标准档；用户明确要求某档时保留该档特色。

## 执行流程

1. **锁定事实。** 在内部识别谁做了什么、当前状态、数字及口径、期限、归因、下一步；不把整理过程写进答案。
2. **确定主线。** 长文从“业务目标 → 问题或卡点 → 关键抓手 → 结果或目标 → 下一步”选择有素材支撑的部分；短句只完成局部改写。
3. **赋予结构。** 把已有动作归纳为有意义的工作方向；有依据才写“能力沉淀、机制建设、业务价值”。保留必要的技术细节与因果关系。
4. **调节语言。** 依照所选浓度加入风格词和句式，确保每个抽象词能对应一个对象、动作或判断。需要更多语感或场景样例时读取 [表达与场景示例](references/style-examples.md)。
5. **核对后输出。** 检查改写前后的事实、状态、数字和承诺是否一致，删去没有信息作用的重复表述，交付成稿。

## 写出辨识度

优先使用下列有意义的转换，按场景择取，不连成固定套话：

| 普通说法的意图 | 可用表达 | 使用条件 |
| --- | --- | --- |
| 把目标讲清楚 | 拉齐目标、对齐预期、明确结果口径 | 说清楚对齐的对象或内容 |
| 找到重点 | 聚焦核心矛盾、识别关键卡点、找到抓手 | 指出重点是什么 |
| 解决一个问题 | 打透问题、推进落地、补齐短板 | 保留“进行中 / 已完成”的区别 |
| 把办法长期用起来 | 沉淀方法、形成机制、复用能力 | 有重复使用或固化流程的依据 |
| 多方一起推进 | 拉通链路、形成合力、明确 owner | 不虚构已有共识或负责人 |
| 做到有结果有反馈 | 验证效果、完成闭环、对结果负责 | 已闭环须有完成与验证事实 |
| 解释为什么做 | 站在业务视角、回到目标、拆解底层逻辑 | 明确对应的业务目的 |

用“围绕……，以……为抓手，推进……”承接动作，用“当前卡点在……，下一步……”交代进度，用“将……沉淀为……”表达有依据的复用方向。爆炒档可适量加入“这件事的核心命题是……”“先拉齐一个共识……”“把……从单点动作升级为体系化打法”等句式。

让各句承担不同信息，避免连续三句只有“赋能、协同、价值、生态”等抽象名词。不要将普通修复自动升格为战略突破，也不要把每项工作都包装成平台或中台建设。

## 按场景组织

- **周报 / 项目进展**：先给阶段结论，再写关键动作、卡点和下一步；区分已完成、进行中、计划中。
- **述职 / 简历素材**：按背景、个人职责、关键判断、具体动作、可核实结果组织；保留“参与、负责、主导”的贡献边界。
- **复盘**：按目标、实际结果、差距、原因、改进动作组织；把推测原因与已确认原因分开。
- **方案 / 立项**：按问题、目标、方案抓手、依赖、风险、验收方式组织；把建议写为建议，把预计收益写为预计。
- **OKR**：目标写清方向，KR 写可验证的结果；用户未给指标或日期时标记必要的待定项，或给明确标注的建议值，不能充当既定承诺。
- **会议发言 / 向上沟通**：先结论，再给依据、卡点或需要的决策；沟通请求必须具体。
- **聊天 / 一句话**：就地改写，保持原来的沟通意图与尺度，不扩成正式报告。

只选用适用的结构，不为填满模板补造内容。

## 保持事实与边界

- 原样保留数字、单位、基线、时间范围、专有名词和明确限定；不要擅自把“百分点”改成“百分比”，或把测试结果改成生产效果。
- 保留“拟、计划、预计、可能、待验证、尚未”等状态词。准备做不等于已经做，方案评审不等于能力上线，未验证不等于已经拿到收益。
- 不新增业绩、承诺、用户反馈、因果关系、完成时间和负责人的姓名。可以提出新动作，但必须用“建议、可考虑、拟”等清楚标为建议。
- 缺少数据时，改写任务直接保留定性描述；正式起草只有确实必要时使用少量“[待补充：指标口径]”类占位符。不要因风格转换而追问无关背景。
- 事故、延期、投诉等内容，先直说实际影响和责任边界，保留必要的措施与时间。不要用“阶段性承压、认知升级”等词掩盖事实；风格词只用于不影响理解的部分。
- 批评落在行为与影响上，不把工作问题改写为“认知低、格局小、缺乏主人翁精神”等人格评判。
- 用户要求模仿语气时，不额外赋予真实公司的背书、具体高管身份或内部消息来源。

## 输出约定

默认只给用户要求的成稿，不附上选档过程、词汇清单、长篇分析或自我评价。遵守用户给定的字数、段落和平台格式；一次默认给一版，只有要求对比时才并排给多档。

翻译成人话时，先直接解释真实含义；只有缺失信息影响理解时，补一句“这段没有说明……”并列出最关键的缺项。不要臆测说话人的动机，也不要把黑话中的意向解释成已完成的结果。

仅做风格改写时使用现有素材即可。任务需要新增外部事实时，另行核实并按要求标注来源。写好文案不代表获得发送、发布或替用户承诺的授权。
